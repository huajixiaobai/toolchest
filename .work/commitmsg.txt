新增「得分计算器」标签页：按游戏自己的结算顺序算分

用户提议：这游戏的核心是通过各种机制凑分，那就做一个得分计算器。

- 结算顺序严格照 tools/state_events.lua 的 evaluate_play：
  ① 牌型基础（含等级成长）→ ② 每张打出的牌（点数 + 强化 + 版本 + 蜡封重复 + 逐牌小丑）
  → ③ 留在手里的牌（钢铁 ×1.5）→ ④ 每个小丑（版本 → 主效果，按位置从左到右）→ ⑤ 手填修正
  最终 = floor(筹码 × 倍率)，右侧给出**逐行账目**（每一步之后的 筹码 × 倍率）
- 小丑规则不是手抄的：新增 .work/gen-rules.js 从游戏自己的 card.lua
  （Card:calculate_joker 的 individual / repetition / other_joker / main 四段）抽出
  58 条具名规则 + 4 条通用配置规则（t_chips / t_mult / x_mult / Suit Mult），
  生成后注进 app.js 的标记块，所以单文件版与站点版都能用，游戏更新后重跑一次即可
- 覆盖度在界面上如实标注：自动 / 按打出的牌判定 / 重复触发 / 需手填（依赖运行时状态的
  20 条会列出来，并给每张小丑留了手填 +筹码/+倍率/×倍率 的输入框）
- 概率类（幸运牌、8 球、骰子…）不参与计算，界面上写明了
- 测试：新增 scoreCalc 场景，验算 4 个能手算的例子
  一对 J + 小丑 = 180；一对 A + 贪吃鬼 = 160；奖励牌+闪箔 = 220；红蜡封+留手钢铁 = 75
  桌面与手机（390×844）都跑，全部通过
- 顺带：debug 接口暴露 B.score（state / compute / rules），便于脚本化验证
